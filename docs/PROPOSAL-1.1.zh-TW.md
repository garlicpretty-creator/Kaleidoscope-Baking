## 2. 1.1 主題：「看得見、擺得出來」

1.0 的站點能用，但**只能靠訊息文字知道裡面有什麼**，做好的飲料也只能拿在手上。1.1 的重點：

1. **看得見**：站點裡的東西直接顯示在方塊上。
2. **擺得出來**：飲料、點心可以擺上桌、放進展示櫃，麵包店與咖啡館真的能布置。
3. **補齊 1.0 缺口**（§1）。
4. **廚房整合加深**：奶油入炒鍋、牛奶入湯鍋。
5. **系列互通落地**：拿到漁歌、豐收、草本、樂牧的正式 ID 後啟用，並加上反向註冊。

## 3. 看得見、擺得出來

### 3.1 站點內容視覺化

新增一個共用的**展示實體** `kaleidoscope_baking:display`：
- 不可互動、無碰撞、不會存檔遺失；
- 用來在方塊上顯示一個物品；
- 每個站點依狀態生成或移除；
- 參考廚房石磨的作法：同一個站點只保留一個展示實體，重新載入區塊時自動修復。

| 站點 | 顯示內容 |
|------|---------|
| 烤箱 | 爐門前方顯示正在烤的第一格物品；完成時上方冒出「完成」粒子 |
| 攪拌盆 | 盆內顯示最後放入的材料；攪拌時旋轉 |
| 發酵籃 | 改用方塊狀態，0–3 段麵團逐漸膨脹（不需實體，較省效能） |
| 裱花台 | 顯示目前的底座與最上層配料 |
| 咖啡機 | 完成時出水口下方出現杯子 |
| 手沖架 | 放入咖啡粉後顯示濾杯有粉 |
| 雪克杯 | 搖杯時晃動動畫（方塊狀態切換兩幀） |

> 效能原則：一個站點最多一個展示實體；發酵籃、雪克杯這類能用方塊狀態表現的就不用實體。

### 3.2 擺放與展示

| 新方塊 | 玩法 |
|--------|------|
| **熱飲杯**（拿鐵、卡布奇諾、摩卡、熱可可、手沖咖啡…） | 改用廚房公開的 `kaleidoscope_cookery:cup_stack` 元件：手持熱飲對地面或桌面使用即可放下，同一格最多疊 4 杯，空手拿回 |
| **手搖杯** | 烘焙自己的擺放元件，一格最多 4 杯；**保留每杯的甜度和冰塊**（存在方塊的世界資料裡），拿回時還原 |
| **蛋糕架** `cake_stand` | 放一個整顆甜點，墊高展示，一樣能一片一片吃 |
| **三層點心架** `tea_tray` | 放 3 個小點心；從架上吃東西時，下午茶加成的時間窗從 30 秒放寬到 60 秒 |
| **麵包展示櫃** `bread_display` | 9 格收納、玻璃正面，顯示前 3 格內容；比較器可讀取存量 |
| **甜點櫥窗** `pastry_case` | 同上，**放在裡面的甜點不會壞**（為之後的「新鮮度」系統預留，1.1 不做新鮮度） |

## 4. 新點心

### 4.1 千層酥皮與西點

- **千層酥皮** `puff_pastry`：
  - 派皮麵團 + 奶油 ×2 → 攪拌盆 → 千層麵團；
  - 千層麵團 → 廚房砧板 + 擀麵棍，擀 3 次 → 千層酥皮。
  - 3 次是砧板工具配方串成三段：一擀、二擀、三擀，各有中間物品。

| 成品 | 做法 |
|------|------|
| 拿破崙派 | 裱花台：千層酥皮（烤）→ 卡士達 → 千層酥皮 → 糖 |
| 蝴蝶酥 | 千層酥皮 + 砂糖 → 烤盤 |
| 葡式蛋塔 | 千層酥皮 + 卡士達 → 瑪芬烤盤（與 1.0 蛋塔區隔：口感、效果不同） |
| 酥皮濃湯 | 廚房湯鍋做的任一湯品 + 千層酥皮 → 烤箱（**直接使用廚房成品**的跨模組食譜） |
| 瑪德蓮 | 新模具 `madeleine_mold`；麵粉 + 蛋 + 奶油 + 糖 + 檸檬 → 瑪德蓮 ×6 |

### 4.2 中式酥點

| 成品 | 做法 | 新材料 |
|------|------|--------|
| 蛋黃酥 | 千層酥皮 + 鹹蛋黃 + 芝麻醬 → 烤盤 | **鹹蛋**：雞蛋放在廚房竹篩用「濕式」（淋雨 / 滴水石）醃製 → 鹹蛋 → 砧板 → 鹹蛋黃 |
| 鳳梨酥 | 酥皮麵團 + 鳳梨醬 → 新模具「鳳梨酥模」 | **鳳梨**：水果類，見 §8 待確認 |
| 馬拉糕 | 麵粉 + 黑糖 + 蛋 + 奶油 → 廚房蒸籠 | — |

### 4.3 糖霜餅乾

- 新工具**擠花袋** `piping_bag`。
- 新材料**糖霜** `icing`：砂糖 + 蛋 → 攪拌盆；糖霜 + 染料 → 6 色糖霜（白、粉、藍、綠、黃、可可）。
- 新模具**餅乾切模** `cookie_cutter`：
  - 奶油餅乾麵團 + 切模 → 烤盤 → 原味造型餅乾；
  - 造型餅乾 + 色糖霜 → 裱花台 → 6 色**糖霜餅乾**（各為獨立物品，可堆疊）。
- 6 色是為了控制物品數量；之後要擴充到 16 色時，改用方塊擺放 + 動態屬性。

## 5. 廚房整合加深

### 5.1 奶油與牛奶進入廚房站點

| 廚房能力 | 1.1 用法 |
|---------|---------|
| `oil_containers` | 新物品**奶油罐** `butter_jar`（裝 8 份奶油）註冊為油容器：廚房炒鍋可以用奶油代替油，炒出「奶油香」版本（法式吐司、鬆餅改用奶油罐） |
| `stockpot_base_containers` | 牛奶桶註冊為湯鍋基底 `kaleidoscope_baking:milk`：卡士達、熱可可、奶油濃湯改成**牛奶基底**的正規湯鍋食譜（1.0 的水基底版本保留為相容） |

### 5.2 食譜書

- 外部模組透過烘焙 API 註冊的配方，**也會出現在食譜書**。
  - 1.0 只在世界載入時發布一次，之後註冊的看不到。
  - 1.1 改為：註冊變動後等 2 秒，用新版本號重新發布。
- 設定頁能顯示**目前的實際值**。
  - 1.0 的自動轉換開關一律預設開啟，不反映世界設定。
  - 1.1 改為：世界設定變動時，同步寫到每位玩家的屬性上，廚房表單就會讀到正確的值。

## 6. 烘焙 API（仍為 v1，只新增、不破壞）

新增的能力會出現在 `api_ready` 的 `capabilities` 中，舊的附加模組完全不受影響。

| 新事件 / 能力 | 用途 |
|--------------|------|
| `kaleidoscope_baking:query_ingredient` → `ingredient_info` | 查詢某物品屬於哪些 `kaleidoscope:*` 標籤（1.0 企劃已列但未實作） |
| `kaleidoscope_baking:caffeine_adjust` | 其他模組調整玩家咖啡因值（例如草本的安神茶 −2） |
| 公開方塊元件 `kaleidoscope_baking:dessert` | 其他模組的整顆甜點方塊可直接使用烘焙的「分片食用」元件（比照廚房公開 `cup_stack` 的作法），參數：片數、每片飽食度、切片物品 |
| 公開方塊元件 `kaleidoscope_baking:drink_cups` | 其他模組的手搖飲也能擺放並保留甜度 / 冰塊 |
| `register_display_rule` | 指定物品在烘焙展示櫃 / 站點上顯示為物品或方塊模型（比照廚房） |
| 食譜書即時更新 | 見 §5.2，外部模組不需任何改動 |

## 7. 系列互通落地

**前提：取得漁歌、豐收、草本、樂牧的正式命名空間與物品 ID。**

1. 把 `BP/scripts/compat/series.data.js` 的暫定 ID 換成正式 ID。
   - 1.0 的引擎已完成並測試過：配方互通、產出改給主導版、植株自動轉換。
2. 自動產生 1:1 互換的工作台配方（產生器依對照表產出 JSON；未知 ID 不產生，避免錯誤）。
3. **反向註冊**：烘焙新增 3 種副產品，烘焙自己用得到，也透過對方 API 送給其他模組。

| 副產品 | 來源 | 烘焙內用途 | 送給 |
|--------|------|-----------|------|
| 麵包屑 `bread_crumbs` | 吐司 / 法棍 → 砧板 | 炸物裹粉（廚房炒鍋） | 漁歌：魚餌 |
| 咖啡渣 `coffee_grounds` | 咖啡機、手沖架每次沖煮 | 對烘焙植物當骨粉用（一次 +1 階段） | 草本 / 豐收：肥料 |
| 果渣 `fruit_pulp` | 做果醬、檸檬水 | 堆肥桶 | 豐收：堆肥；樂牧：飼料 |

4. 若四個模組的 API 事件名稱與烘焙不同，在 `compat/` 各寫一份轉接，不動核心。

## 9. 技術風險

| 風險 | 影響 | 對策 |
|------|------|------|
| 展示實體數量多時的效能 | 麵包店擺很多站點會卡 | 每站點最多 1 個；能用方塊狀態表現的不用實體；實體只在玩家 32 格內同步 |
| 展示實體與方塊不同步（區塊載入、指令移除） | 殘留或消失 | 比照廚房石磨：互動時檢查、區塊載入時修復、找不到主方塊就自我移除 |
| `cup_stack` 是廚房文件公開的元件，但每種熱飲都要一個方塊 | 方塊數量增加 | 只做熱飲（10 種）；手搖飲用烘焙自己的通用擺放方塊（一個方塊、狀態記錄杯數） |
| 手搖杯擺放要記住每杯的甜度 / 冰塊 | 存檔資料增加 | 只存兩個短字串 × 4 杯，按位置存世界動態屬性；方塊移除即刪除 |
| 牛奶基底需要廚房湯鍋接受自訂基底 | 若不支援，牛奶食譜無法運作 | 1.1 開工時先做原型確認；不支援則維持 1.0 的水基底 |
| 食譜書重新發布太頻繁 | 傳送量大 | 註冊變動後等 2 秒合併成一次；只有在變動時才發布 |

## 10. 待確認事項

1. **1.0 實機測試結果**（1.1 開工前提）。
2. 漁歌、豐收、草本、樂牧的**正式命名空間、物品 ID、API 事件名稱**（§7）。
3. **鳳梨**由烘焙自帶，還是交給豐收？
   - 依主導規則，水果類兩個都裝時以豐收為主；
   - 問題在於：只裝烘焙時要不要有鳳梨酥？
4. 糖霜顏色 6 色是否足夠？
5. 甜點櫥窗預留的「新鮮度 / 會壞掉」系統，之後是否要做？做的話會影響所有食物的設計。
6. 熱飲擺放用廚房的 `cup_stack`，杯子外觀會跟廚房茶杯一致。是否接受，還是要烘焙自己的馬克杯造型？

## 11. 開發階段

依序進行，不設排期。

| 階段 | 內容 | 驗收標準 |
|------|------|---------|
| **1.1-A 補缺口** | §1 全部項目 | 1.0 企劃列出的物品、工具、模具都存在且可製作 |
| **1.1-B 視覺化** | 展示實體、站點顯示、發酵籃 / 雪克杯方塊狀態動畫 | 每個站點不用看訊息就能知道裡面有什麼；重新進世界後顯示正確、不殘留 |
| **1.1-C 擺放** | 熱飲杯、手搖杯、蛋糕架、點心架、展示櫃、櫥窗 | 手搖杯放下再拿回，甜度 / 冰塊不變；拆方塊不掉物品 |
| **1.1-D 新點心** | §4 全部 | 每道新點心有配方、食譜書條目、效果 |
| **1.1-E 廚房整合** | 奶油罐、牛奶基底、食譜書即時更新、設定頁顯示實際值 | 外部範例包在進世界後才註冊的配方，也能在食譜書看到 |
| **1.1-F API** | §6 | 新事件有文件、測試；舊範例包不改也能運作 |
| **1.1-G 系列互通** | §7（拿到 ID 後） | 任意組合安裝都能載入；主導版規則正確 |
| **1.1-H 測試與發佈** | 自動測試、實機測試 | 自動測試全過；實機跑過所有新站點與擺放 |
